안녕하세요. 오늘은 SQL 조회 성능에 영향을 주는 Join에 대해서 공부해보도록 하겠습니다. Index를 추가적으로 공부하고 생성해보려고 했으나, 예전 Index 관련해서 포스팅한 글이 있어서 내용이 겹칠 것 같아 링크만 첨부하고 Join에 대해서 공부해볼까 합니다.

## 1\. Join 이란? 

\- 관계형 데이터 베이스 (RDBMS) 에서는 데이터의 중복을 막고 일관성을 유지하기 위해서 데이터를 여러 공간 (테이블)에 잘개 나누어 저장하는데, 이때 Join은 이렇게 나뉘어 저장된 데이터들을 공통된 기준값 (Key) 을 이용해 다시 하나의 정보로 결합하는 논리적 연산이다. 즉, 분산된 정보들 사이의 관계를 파악하여 나뉘어있는 정보를 엮어내는 작업이라고 생각하면 좋습니다.

대표적인 Join 연산으로는, Inner Join, Outer Join, Cross Join, Self Join 등이 있는데, 실제로는 Inner Join과 Left Outer Join을 많이 사용합니다. Join에 대해서 예제와 함께 살펴 보겠습니다.

## 2\. Inner Join

![](__MEDIA__/140eab2499bd5ede009a0b561256c20c32e543bd85700233e0733c5cc2e10672.png)

공통 분모를 조회하여 출력하는 Inner Join

*   Inner Join : 두 데이터의 집합에서 기준점이 정확하게 일치하는 값 (교집합) 들을 골라내어 결합해 출력하는 Join, 짝을 찾지 못한 데이터는 출력되지 않는다.

위의 테이블을 볼 때, dept\_id 컬럼이 두 테이블 모두 존재하는 것을 볼 수 있다. 그럼 여기서 우리는 교집합인 dept\_id 컬럼을 기준으로 Inner Join을 실행할 수 있다. 아래는 문법 예시이다. 

SELECT \[조회할 컬럼명\]

FROM \[첫번째 테이블\]

INNER JOIN \[조인할 두번째 테이블\] 

ON \[첫번째 테이블에서 Join 컬럼 명\] = \[두번째 테이블에서 Join 컬럼 명\];

```
/* Inner join */
SELECT E.emp_name, D.dept_name
FROM Employees E
INNER JOIN Departments D 
ON E.dept_id = D.dept_id;
```

## 3\. Outer Join

![](__MEDIA__/660f316c2109193f14a622e48979fe57b92732cc3faeb97d0629a5879192b67e.png)

Left Outer Join, Right Outer Join

![](__MEDIA__/e4ab2934f1eaf6500532ebbe85bbcca6cb432973c6a3420c2ab526a812fda430.png)

Full Outer Join

*   Outer Join : 조건이 일치하지 않아도, 기준이 되는 쪽의 데이터를 버리지 않고 모두 보존한다 (NULL 출력). 기준의 위치에 따라 세 가지로 나뉜다.
*   Left (Outer) Join : 왼쪽 테이블의 모든 데이터를 유지하고, 오른쪽 테이블에서 일치하는 값을 찾아 우측에 출력한다. 맞는 짝이 없다면 NULL값을 출력한다.
*   Right (Outer) Join : 오른쪽 테이블의 모든 데이터를 유지한다. 동작 원리는 LEFT JOIN과 같고 데이터의 추출 방향만 오른쪽이다.
*   Full (Outer) Join : 양쪽 테이블의 모든 데이터를 유지한다. (전부 출력) 일치하는 짝이 없는 빈 공간은 양쪽 모두 NULL로 채워진다. (MySQL, Maria  에서는 Full Outer Join을 지원하지 않는다. Oracle 등 타 RDBMS 에서는 FULL JOIN 으로 칭하기도 한다.)

Left Outer Join과 Right Outer Join 의 SQL 구문 예제는 아래와 같다. Outer Join의 경우에는 NULL 값도 함께 출력이 가능하다. 

SELECT \[조회할 컬럼명\]

FROM \[첫번째 테이블\]

LEFT OUTER JOIN / RIGHT OUTER JOIN \[조인할 두번째 테이블\] 

ON \[첫번째 테이블에서 Join 컬럼 명\] = \[두번째 테이블에서 Join 컬럼 명\];

```
/* Left outer Join */
SELECT E.emp_name, D.dept_name
FROM Employees E
LEFT OUTER JOIN Departments D 
ON E.dept_id = D.dept_id;
```

![](__MEDIA__/1683bac0b548fd5e47b6b0d82240483e97e6917650fa4f42f10649d96f347391.png)

Left Outer Join 결과

Right Outer Join 은 기존의 LEFT Outer Join 에서 Right 로 구문을 변경하면 되므로 위의 예제를 참고하면 될 것 같다.

```
/* Right outer Join*/
SELECT E.emp_name, D.dept_name
FROM Employees E
RIGHT OUTER JOIN Departments D 
ON E.dept_id = D.dept_id;
```

![](__MEDIA__/9b91e71509fb6a4ac04293ff430363bb841151620140943237e7baca0a03bf68.png)

Right Outer Join 결과

Outer Join 의 경우 위에서 말한대로, MySQL Maria 에서는 지원하지 않는다. 대신 Left Outer Join 과 Right Outer Join을 Union 으로 결합해서 중복 출력되는 값을 제외한 나머지 값을 출력 할 수 있다.

만약, 성능적으로 개선시키고 싶다면 Join 구절에 WHERE 조건을 주어 IS NULL 조건으로 NULL 값은 제외하고 출력이 가능합니다. (사실상 Full Outer Join을 사용하는 경우는 거의 없습니다.) 

```
/* Full Outer Join */
SELECT E.emp_name, D.dept_name
FROM Employees E
LEFT OUTER JOIN Departments D ON E.dept_id = D.dept_id
UNION
SELECT E.emp_name, D.dept_name
FROM Employees E
RIGHT OUTER JOIN Departments D ON E.dept_id = D.dept_id;
```

## 4\. Cross Join과 Self Join

*   Cross Join : 두 테이블의 데이터를 곱하여, 가능한 모든 조합을 만들어 출력해내는 Join. Join 조건이 따로 존재하지 않는다.

실제 Dummy Data를 생성해 내거나, 매트릭스를 생성할 때 사용하지만 일반적으로 많이 사용되는 Join은 아니니 개념만 알아두고 넘어가도 좋을 듯 하다.

4\*4 의 모든 경우인 총 16개의 행이 출력된다. Join 조건을 붙이지 않고 실행하는 경우 Cross Join이 실행되어 자원을 과도하게 사용할 수 있으니 주의해야 한다. 

```
/* Cross join */
SELECT E.emp_name, D.dept_name
FROM Employees E
CROSS JOIN Departments D;
```

![](__MEDIA__/bedfa91b4fbb325a31ebdc2a03d7d315e4e9f0beec368f795194829b4af5bd90.png)

Cross Join 조회 결과

*   Self Join : 말 그대로 하나의 테이블을 두 번 불러와서 조인하는 방법으로, Self Join 이라는 명령어는 존재하지 않지만 Inner Join 이나 Left Join 을 사용하면서 테이블에 Alias 를 다르게 지정하여 두 개의 테이블인 것 처럼 Join 하는 것 이다.

동일 테이블 내의 데이터를 비교하거나, 계층 구조를 표현할 때 많이 사용하는 방법으로 실무에서도 종종 사용한다. 

아래 Employees Table에서 manager\_id 와 emp\_id 의 값이 같은 것을 Join 하는 쿼리를 작성하였다. Left Outer Join이 아닌 Inner Join도 동일하게 사용이 가능하다. 

```
/* Self Join */
SELECT 
    E1.emp_id AS "사번",
    E1.emp_name AS "부하직원",
    E2.emp_name AS "관리자"
FROM Employees E1
LEFT JOIN Employees E2 ON E1.manager_id = E2.emp_id;
```
