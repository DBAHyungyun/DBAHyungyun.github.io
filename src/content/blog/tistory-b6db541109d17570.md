Always On 설치 테스트 기본 구성

OS : Window Server 2019 

DB : MSSQL 2016 Enterprise(SP2)

필요 서버 총 3대 : AD 서버 (도메인서버) / AG 서버 2가지 (Always On Primary Node / Secondary Node)

* * *

윈도우 클러스터 구성이 완료 되었다면 이제 DB에서 작업을 진행해주어야 한다.

SQL Server 구성 관리자를 켜고, SQL Server 서비스를 설정해줘야 하는데, SQL Server 우클릭 -> 속성 -> Always On 고가용성 그룹 체크

\-> 위 설정을 적용 하려면 DB를 재시작 해주어야한다.

Always On 고가용성 그룹 설정

만약 Failover Cluster 구성이 정상적으로 되어 있지 않은 경우에는 해당 메세지가 출력되면서 Always On 구성 자체가 불가능하게된다.

![](__MEDIA__/9b2477e17c98fb475c95e380520ab4546ad311cbc73a1a27cec85105450326ca.png)

Failover Cluster 재확인 필요

이외에 실제로 Always On 구성 가능 여부를 확인하려면, SSMS 에서 서버 -> 인스턴스 -> 우클릭 속성 -> HADR 사용 옵션이 True로 되어있는지 확인하고 Always On 인스턴스 연결이 가능하다.

![](__MEDIA__/14dd4612b1891a1a4e7e7875cd8e372d897669c671f4e9016bd187c2b8a8849a.png)

서버 인스턴스 우클릭

![](__MEDIA__/eb1f239d677cb73a96b69539a4efca1573604635c97391f3ba366f92cffb37b6.png)

속성에서 HADR 사용 옵션 True

또, 쿼리로도 알아 볼 수 있는데

SELECT SERVERPROPERTY ('IsHadrEnabled'); 쿼리를 사용해 결과값이 1인 경우 연결이 가능한 상태로 나온다.

![](__MEDIA__/bd5d5c7388b7c479f5bd794b4c3b595e5edbd9c133c7aa340c7061ffe82a403f.png)

쿼리 결과값

이외에도 몇가지 방법이 더 있으나, 이정도로만 진행하고 이제 처음 포스팅에 만들어준 공유폴더에 데이터베이스를 생성하고, 이 데이터베이스를 활용하여 고가용성 그룹을 선택한다.

![](__MEDIA__/fa9a084a0958d55fbe3a5d914409dfe206632a79342f91069b4f216604762acb.png)

데이터 베이스 생성

종종 로그온이 지정되어 있지 않고, 서비스가 지정되어 있지 않아서 해당 폴더에 대한 도메인의 권한이 없다는 알림이 나올때가 있다. 그런 경우에는 작업 관리자 -> 서비스 -> SQL Server 속성 -> 로그온 권한을 해당 도메인에 맞는 user 혹은 Administrator 에 부여한 뒤 실행하면 된다.

![](__MEDIA__/37bbe86a8b27d35c0d46978b61443bb39fd1d4158c8de2dcc91b0d3b52721acd.png)

데이터 베이스 선택

여기까지는 잘 수행하였으나, 종종 아래 add Replica 복제본 추가 쪽에서 Secondary Instance로 나와야 할 부분이 안나오는 경우가 생긴다. 이 경우에는 방화벽이나 네트워크 설정이 안되어 있을 경우가 상당히 높다.개인서버에 진행하면 방화벽을 모두 내려도 좋고 포트 바인딩만 해주어도 무방하다. 방화벽을 모두 내리고 SQL Configure 구성 관리자에서도 Enable 상태인지 확인 한 뒤 다시 적용하게 되면, 

![](__MEDIA__/9a51b3071db64eb5feb7f9c8ab28f6390c2a6b6440748ba3c8e6f61f1293754d.png)

추가가 안되는 화면

![](__MEDIA__/c23cdd03a9831842874d26a76f693b53e0c7e3dc1602e5ba66afa0e6de897c8b.png)

SQL Server 네트워크 구성 관리자

![](__MEDIA__/447ba6367ab08381124e2a0ee0419b45f62a6a6ed1020c90730144613871fadc.png)

방화벽 정보 확인

Add Replica 를 클릭해서 Server name에 등록하려는 Secondary Always On 서버 정보를 입력하고, Connected 하게 되면 정상적으로 Add Replica 가 수행 가능하며, Automatic Failover 체크박스를 클릭하여 자동 장애 조치가 가능하도록 설정하면 된다.

실제 운영 환경에서는 Windows Authentication 즉, 윈도우 인증 방식으로 운영하는 경우는 거의 없다. 보통 계정을 생성하여 계정 인증방식으로 사용하게 되는데, 현재는 테스트 환경이므로 윈도우 인증 방식을 사용하였고, sa 계정이나 개인 계정을 사용하여 연결해도 무방하다.

정상적으로 Add Replica가 된 모습

자동으로 시드 데이터를 싱크할 지, 아니면 Full Database 에 대한 데이터와 로그를 백업 할지, 조인만 선택할 지, 초기 데이터 동기화를 건너 뛸 지 선택 할 수 있다.

![](__MEDIA__/ba7e85ddc13b3fff2613286253b026fdd4a8773d3ebe66ae3fa14427c5c71473.png)

데이터 동기화 선택 옵션

최근 버전에서는 자동으로 시드 데이터를 선택하여 고가용성 그룹에 백업하고 표현하지만 실습환경에서는 Database를 생성해주었고 그 경로 또한 공유하였으니, 두번째 Full Database and log backup 을 선택하고 경로를 지정해주자.

![](__MEDIA__/368b762eeb7a5830914d4114b7eafd3200f3f2ecb453ef75a3603e76a728bb13.png)

Full Database and log backup 선택

리스너, 수신기에 대한 경고창이 발생하였지만, 현재 우리는 리스너를 구성하지 않았으므로 Next 넘어가면 된다.

마지막으로 Finish 를 클릭하면, endpoints 작업이 진행되고 성공적으로 설치를 마무리 할 수 있다.

구성 완료

이렇게 Always On 구성 테스트를 진행했는데, 다음에는 이 구성된 서버를 바탕으로 실제 SYNC가 정상적으로 이루어지고 있는지 확인해보려고 합니다.

구성이 쉽지는 않고, 실제로 운영하는 환경이랑 방화벽 / 보안 정책 / 로그온 방식 등 차이가 있을 순 있지만 테스트 해보는데 충분히 도움이 될 것이라고 생각합니다.
