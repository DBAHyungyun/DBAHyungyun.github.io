지난번 포스팅에서는 오라클의 물리적 저장 구조에 대한 이야기를 다뤘다면, 오늘은 오라클 데이터베이스의 논리적 구조에 대해서 얘기 해보려고 한다.

우선 오라클 데이터베이스의 논리적 저장 구조에는

*   테이블스페이스 (Tablespace)
*   세그먼트(Segment)
*   익스텐트(Extent)
*   데이터 블록(Data Block)

이렇게 4가지 저장구조를 들 수 있는데, 

테이블 스페이스는, 데이터베이스 내의 가장 큰 논리적인 저장 단위로, 여러가지의 데이터 파일을 포함 한 것이다.

\- 데이터는 테이블 스페이스 내에 저장되며, 여러가지 테이블 스페이스를 생성하여 데이터 관리를 최적화 할 수 있다.

![](__MEDIA__/bf44f202fd9fd855e000d15bbbb72a98b97d2a3cb6e36352976df50d1bd67dfa.png)

Oracle Database Tablespace 구조

이런 테이블 스페이스의 기본 적인 종류에는 6가지가 있으며 간단하게 설명하자면,

SYSTEM : 오라클을 구성하는 필수 테이블 스페이스이며, 데이터 사전이 저장되는 곳이며 용용 프로그램 데이터에 사용해서는 안되는 테이블 스페이스

SYSAUX : 보조 데이터 사전 및 데이터베이스 관리 정보가 저장되는 필수로 구성되어야 하는 테이블 스페이스로 응용 프로그램 데이터에 사용해서는 안되는 테이블 스페이스

UNDO : ACID를 보장하기 위해 트랜잭션 롤백을 위한 UNDO 정보가 저장되는 테이블 스페이스

TEMP : 정렬 및 임시 작업을 진행하기 위한 테이블 스페이스 

USERS : 사용자의 데이터가 저장되는 테이블 스페이스

EXAMPLE : 예제 데이터 및 샘플 스키마를 저장하는 테이블 스페이스

세그먼트란? 

\- 세그먼트는 테이블스페이스 내부에서 논리적으로 데이터를 저장하는 단위입니다. 

\- 여러개의 Extent로 이루어져 있습니다.

![](__MEDIA__/1232261bcec29f4b327feeb79d8001c8a6ccac1457e941275500681ab44b7c07.png)

Oracle Segment

이런 세그먼트의 종류 4가지를 설명하면,

데이터 세그먼트 : 테이블 또는 클러스터 데이터를 저장하는 세그먼트

인덱스 세그먼트 : 인덱스 데이터를 저장하는 세그먼트

UNDO 세그먼트 : 트랜잭션의 롤백 및 읽기 일관성을 유지하는 세그먼트

TEMP 세그먼트 : 정력 작업 등의 임시 데이터를 저장하는 세그먼트

* * *

익스텐스란?

\- 세그먼트 내부에서 연속된 데이터 블록의 묶음 입니다.

\- 테이블이나 인덱스가 커지면 자동적으로 추가 익스텐트를 할당하고, 자동 확장을 지원하여 공간 관리를 원활하게 합니다.

데이터 블록이란?

\- 오라클에서 데이터를 저장하는 가장 작은 논리적 단위입니다.

\- 블록의 크기는 2KB, 4KB, 8KB, 16KB 등으로 설정이 가능하고, 블록헤더, 트랜잭션 슬롯, 데이터 영역의 구성요소를 가집니다.
