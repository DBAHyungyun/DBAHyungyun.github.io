오늘은 RDS Maria DB 에서의 Majon Upgrade 과정에 대해서 정리하려고 합니다.

개인적인 테스트 환경에서는 여러가지 고려사항을 생각하지 않고 업그레이드를 진행하면 되지만, 운영의 경우에는 여러가지 상황을 고려해서 신중하게 업그레이드를 진행해야 합니다. 

파라미터나, Database에 직접적인 영향이 있는 패치 작업은 개발/검증 서버에서 우선적으로 패치를 진행한 뒤, 운영서버에 적용하는것이 원칙입니다. 다만, 적용시기가 촉박하고 비용등의 문제로 개발/검증 서버를 운영하기 어려운 상황이라면 Case Open이나, MySQL/Maria Community를 활용하여 변경되는 파라미터 값과 패치 노트를 꼼꼼하게 확인해야합니다.

* * *

테스트 환경 : AWS RDS Maria DB 10.6.19 Version 

업그레이드 버전 : Maria DB 10.11.15 Version

![](__MEDIA__/95c3dc591c42f17e40272db2e00d796dc277d21d039ca20dcfeb32eb80b7e992.png)

Maria 10.6.19 Version 인스턴스

우선, 10.6.19 버전의 인스턴스를 생성해줍니다.

10.6.19 버전 인스턴스는 10.6 버전의 인스턴스 파라미터 그룹을 사용하고, 정확한 비교를 위해 Default Group 으로 설정해주었습니다.

AWS 는 완전 관리형 Database를 제공하여 업그레이드, 패치 또한 지원해줍니다. AWS의 최대 장점이기도 하고, 사용자가 편리하게 클릭 몇번으로 업그레이드를 진행할 수 있습니다. 업그레이드 과정을 간략하게 확인하면

1\. 인스턴스 우측 상단에 수정 버튼 클릭

![](__MEDIA__/40df6ddda3c6aa5a652ec9866c65191fa6c4c3261a7c76edfd9706559700cfd9.png)

인스턴스 업그레이드 과정

2\. 업그레이드 하려는 버전을 클릭

![](__MEDIA__/bf1cd3b31262fe437ef818c53f0eebe01a4adb79c473f7649747322409916081.png)

업그레이드 버전 클릭

3\. 수정사항 요약 및 즉시 적용 여부 확인

![](__MEDIA__/8384428482db02447aee5e75de1135ec372f04b3ef6c8f39a68baff0b7a27b41.png)

AS-IS / TO-BE 확인

즉시 적용을 하는 경우, 인스턴스 수정을 클릭하자마자 적용이 바로 진행되고, 예약된 다음 유지 관리 기간에 적용하게 된다면 유지관리 기간 중 랜덤한 시간에 AWS가 진행하게 됩니다.

보통의 작업은 새벽시간대 혹은 협의가 된 시간에 진행하기 때문에 즉시 적용으로 진행하는것이 일반적입니다.

이렇게 되면 AWS 에서의 RDS 업그레이드가 마무리 됩니다. (대략 10분 소요) 하지만, 이렇게 간편한 작업이지만 이 작업속 고려해야할 여러가지 확인사항이 존재합니다.

위 캡쳐 사진을 보았을 때, 엔진 버전뿐 아닌 DB 파라미터 그룹과 옵션 그룹이 변경됩니다. 이 그룹들은 사용자가 메이저 업그레이드 당시 파라미터 그룹이나 옵션 그룹을 지정하지 않으면 자동으로 Default 파라미터 그룹을 선택하게 됩니다.

그렇게 된다면, 운영 환경에서 최초 설계된 파라미터와 다른  Defualt 파라미터가 적용이 될테고 timezone, innodb\_buffer\_pool\_size 등 Database 내부에서 아주 치명적인 결함을 일으킬 수 있게 됩니다. 

아래 사진은 Default 10.6.19 버전과 10.11.15 버전의 파라미터 비교 사진입니다.

대부분 의미 없는 파라미터의 삭제, 내부 환경으로의 전환 등 여러이유가 존재하지만, 실제로 어떤 이유로 파라미터가 변경 되었는지 변경된 항목에는 무엇이 있는지 그 파라미터가 운영 환경에 영향을 미치는지 여부를 전부 체크해야합니다. 

![](__MEDIA__/29af2a196f7a06edab70d7ef94520fed9357922ddc3af61bf795bb91e7e7e262.png)

Default 파라미터의 변경값

![](__MEDIA__/ea06e4fe5bbce1ff92052cfe5f2488e59ce05808dd2cf99edc56743bc147542a.png)

실제 파라미터 비교

아래 캡쳐 사진과 같이 모든 버전의 영향도를 체크하고, 설정된 파라미터 값과 동일하게 변경을 진행해주어야지만 문제 없이 업그레이드 작업을 마무리 할 수 있습니다.

![](__MEDIA__/567d2ca75502c7a2e161ae42f31dc42e949fc256b3a7a64a3968e7f67efac5bb.png)

실제 파라미터 및 업그레이드 영향도 체크

이런 고려사항을 모두 체크한 뒤, 업그레이드 즉시 적용을 선택하여 진행하면 아래와 같이 상태탭이 업그레이드 중으로 변경되며 대략 10분뒤 업그레이드가 완료됩니다. 

![](__MEDIA__/1975c57502ba4b9b46b30c423685c2aa708b44866231bc7207fb78ead3ad2902.png)

Maria DB

오늘은 이렇게 Maria DB 업그레이드 과정 및 고려사항에 대해서 기록하였습니다. MariaDB가 아닌 Aurora MySQL, Oracle 등 기타 RDBMS 역시 모두 동일한 방법과 프로세스로 진행됩니다. 업그레이드 이후 운영 시스템에 문제가 생기지 않는것이 최우선 과제이니, 꼭 여러 상황을 고려해서 업그레이드를 진행하길 권고합니다.
