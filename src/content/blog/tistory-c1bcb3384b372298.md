오늘은 오라클에서 쿼리 튜닝과 성능 분석에 꼭 필요한 개념인 인덱스, 성능을 개선시키지만 때로는 저하시키기도 하는 인덱스에 대해서 공부해보려고 합니다.

* * *

DBMS의 테이블에서 데이터를 찾는 방법은 보통 두가지 입니다.

1\. 테이블 전체를 스캔하는 TABLE FULL SCAN 방식

2\. 인덱스를 이용하는 INDEX RANGE SCAN 방식

보통 인덱스라고 하면, 오라클의 쿼리 성능을 개선 시키는 자료구조라고만 생각하는 사람들이 대부분 일텐데, 제대로 되지 않은 인덱스 설계는 성능의 저하를 불러 일으킬 수도 있고, 특정 몇몇의 경우에서는 무분별한 인덱스 사용보다 Table Full Scan 이 더 효율적인 경우도 존재합니다. 

우선, 간단하게 인덱스란?

*   데이터 베이스에서 검색 속도를 향상시키기 위해 사용하는 자료 구조로, 책의 목차와 비슷한 역할을 하고 특정 데이터를 더 빠르고 효율적으로 찾을 수 있도록 도와주는 역할을 하는 객체이다.
*   인덱스는 보통, SELECT 문을 실행할 때, 특정 조건을 만족하는 데이터를 찾기 위해 모든 데이터를 일일이 검색하기 보다는 더 효율적인 조회가 가능하다.

인덱스에는 2가지 탐색 방법이 존재하는데, 나무를 거꾸로 뒤집은 모양의 B-Tree 인덱스와 Bitmap 인덱스 2가지 방법이 존재한다.

우선 가장 많이 쓰이는 B-Tree의 인덱스의 경우 특징을 살펴보면

*   맨위에 뿌리 (Root) 가 맨 위에 존재하고, 가지 (Branch)를 거져 맨 아래 잎사귀 (Leaf) 가 있는 형태이다.
*   리프 노드에는 정렬된 키 값과 ROWID 가 저장된다.
*   ROW ID 는 실제 테이블의 데이터 위치를 가리킨다.

![](__MEDIA__/d30c2d212ac42819e1ede205a1e1a0cfa7d17efb9ffee12c9a13fa03dd858460.png)

인덱스 B-Tree

위 그림과 같은 형태의 B-Tree 인덱스가 된다. 이러한 B-Tree 인덱스에서의 탐색 과정은 수직적 탐색 과정과 수평적 탐색 과정으로 나눌 수 있다.

*   수직적 탐색 과정 : 인덱스 스캔 시작 지점을 찾는 과정
*   수평적 탐색 과정 : 실제 데이터를 찾는 과정 

인덱스의 수직적 탐색 과정은 루트 블록에서 부터 시작하여, 리프 블록까지 빨리 찾을 수 있는 스캔 시작 지점을 파악한다. 이것이 가능한 이유는 각 인덱스 레코드는 하위 블록에 대한 주소값을 갖고 있고 수직적 탐색 과정에 찾고자 하는 값보다 크거나 같은 값을 만나면 바로 직전 레코드가 가리키는 하위 블록으로 이동하여, 시작 지점을 찾게 된다.

이렇게 수직적 탐색을 통해 스캔 시작점을 찾았다면, 찾고자 하는 데이터가 더 나타나지 않을 때 까지, 인덱스 리프 블록을 수평적으로 스캔하게 된다. 실제 데이터를 찾는 과정이다.

비트맵 인덱스는 실제로 많이 쓰이는 방법이 아니라서 간단하게 개념만 확인하자면,

*   카디널리티가 낮은 칼럼에 적합한 인덱스 (ex. 성별, 지역 등)
*   각 값에 대해 비트맵을 사용하여 여러 행의 존재 여부를 비트 (0,1) 로 표현
*   다중 조건 검색에 유리하지만 DML이 많을 경우 성능이 저하 됨

이렇게 Index Scan을 하게 되면, 매번 효율적이라고 생각이 들지만 그렇지 않은 경우도 분명 존재합니다.

인덱스 스캔이 효율적인 상황으로는

*   WHERE 조건절에서 Index 컬럼을 이용한 검색 
*   ORDER BY 의 정렬이 필요한 경우
*   Join 이 필요한 경우 (Join 컬럼에 인덱스가 있는 경우)
*   DISTNCT, GROUP BY 등 연산이 자주 사용되는 컬럼이 있는 경우

반면, 인덱스 스캔이 비효율적인 경우에는 (Table Full Scan 이 유용 할 수 있는 경우)

*   WHERE 조건절이 없거나, 인덱스를 사용하지 않는 컬럼 기준 탐색
*   인덱스 컬럼에 함수나 연산을 사용하는 경우
*   데이터 변경이 빈번한 컬럼 (DML이 많을 수록 인덱스 유지 비용 증가)
*   대부분의 데이터를 조회해야 하는 경우 (ex. 80~90% 이상의 데이터를 조회하는 경우)

항상 Index Range Scan이 성능상의 개선을 야기시킨다고 할 수는 없으나, Index 여부로 성능적으로 많은 개선을 발생시킬 수 있습니다. 필수적인 조건이 아닐지라도 성능 개선하는데에는 때때로 꼭 필요한 것이니 미리 공부해두는것이 좋을 것 같다.
