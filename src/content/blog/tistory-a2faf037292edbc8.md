이번에는 AWS에서 제공하는 기능인 특정 시점으로의 Database 복구인 특정 시점 복구에 대해 기록해보려고 합니다.

시스템을 운영하다보면, 현업에서 필요한 데이터의 유실이나 휘발되어 사라진 해당 시점 데이터를 확인하기 위해서 시점 복구를 요청하는 경우가 종종 있습니다. 

AWS에서는 생성된 인스턴스의 시점 복구 PITR (Point In Time Recovery)를 지원합니다. 특정 시점 복구는 일반 수동 스냅샷, 자동 스냅샷 복구와는 다르고 사용자가 원하는 시점을 복구하기에 원하는 시간대에 데이터를 확인할 수 있다는 장점이 있습니다.

기본적으로 특정 시점 복구란, 자동으로 저장된 자동 스냅샷과, 트랜잭션 로그를 기반으로 복구하게 됩니다.

복원된 개체는 새로운 인스턴스로 생성되어 유지되며, 사용자의 편의에 맞춰 삭제 또는 유지하여 운영하시면 됩니다. AWS의 경우에는 중지된 인스턴스는 일주일 뒤 자동으로 시작되므로 사용하지 않는 인스턴스라면 삭제 하는것이 비용 측면과 자원 관리 측면에서 더 유리합니다.

특정 시점으로 복구하는 방법은

1\. 복구를 원하는 인스턴스를 클릭하고, 우측 작업버튼에 특정시점으로 복원을 클릭한다. 

![](__MEDIA__/e58d6489f3138a5ba6b4cd0dbfd19d3c10f430f633f0a88212ec148f3f4846f7.png)

특정 시점 복구

2\. 클릭해서 특정 시점에 대한 복구를 진행한다. 사용자 지정 날짜 및 시간에 복구를 희망하는 시간을 기입 (초단위 기입이 가능하다.)

![](__MEDIA__/36fd0ebea7b2de8531175fd2789b20b0ecb91d0ba54ad3a5ec68c01719294a79.png)

복구 희망 시점 기입

3\. 아래 인스턴스명과 보안그룹, Subnet 등 기본 세팅이 완료 되고 복구 진행을 클릭하면 복구하려는 인스턴스가 추가로 생성되게 된다.

![](__MEDIA__/f707bcc560a4f7afdac4a51a57cde6fe1b79a2ca1a294e4080704b1af6d9ab1c.png)

인스턴스 생성

4\. 복구가 완료된 뒤, 데이터를 동일하게 조회해보면 지정했던 시점인 2026-01-09 10:09:19.000000 으로 복구된 것을 알 수 있다. 

![](__MEDIA__/9e7625c3f74d25e596f3986fc56f0d195114aa4b9695fa61fdaba8a973c68d1d.png)

데이터 복구

하지만, 여기서 2026-01-09 10:09:19 로 복구 시점을 정했으나, 2026-01-09 10:09:18 의 데이터까지만 보이는데에 의문을 가지는 경우가 존재하는데, 추측하건데 마이크로초 단위의 차이로 데이터가 적재된 것은 10:09:19 로 보이지만, 데이터베이스 내부에서는 밀리초/ 마이크로초 단위까지 기록되어 있을 확률이 높다.

겉으로 보이는 시간은 10:09:19 지만, 실제로는 10:09:19.153480 일 수 있어서 DB가 지정한 복구 시점인 2026-01-09 10:09:19.000000 으로 인식하게 되어 데이터에 간극이 생기는 것으로 추정하고 있다. 

따라서 원하는 시간대에 복구하고, 특정 데이터를 확실하게 확인하기 위해서는 기존의 시간보다 1초뒤인 시점을 복구하여 사용하고 있다.
